# 🌍 Project Manifest & Architecture Context

This document serves as the ground truth for all engineering agents working on the "Domo Agent: Cognitive Video Intercom" project. **Agents must read and adhere to these constraints before generating any code or configuration.**

## 1. Hardware Constraints & Deployment Nodes

* **Node A (Edge Sensor - Outdoor Outpost):**
    * **Hardware:** Raspberry Pi Zero W.
    * **Capabilities:** Extremely limited CPU/RAM. Only responsible for streaming raw camera feed and reading physical GPIO states (doorbell button), and actuating the door-release relay.
    * **IP Address:** `192.168.1.95`
    * **GPIO pinout:**

| Pin | Direction | Function | Physical interface |
|-----|-----------|----------|--------------------|
| GPIO 17 | INPUT (pull-up) | Doorbell detection | PC817 optocoupler ← Fermax call terminal (12Vac) |
| GPIO 18 | OUTPUT | Door-release relay | 5V relay module → Fermax abrepuertas terminal (12Vac) |

* **Node B (Core Processing - Indoor Command):**
    * **Hardware:** Google Coral Dev Board 4GB (Mendel Linux).
    * **Capabilities:** High-performance Edge AI node. The Edge TPU is integrated via **PCIe**, meaning there are NO USB bottlenecks. This node can comfortably handle high-FPS video decoding and inference. 
    * **IP Address:** `192.168.1.44` *(Update before deployment)*.

## 2. Network Topology & Services

All services communicate over the local LAN to ensure low latency.

* **RTSP Video Stream:** Hosted on Node A via `mediamtx`. Accessible at `rtsp://192.168.1.95:8554/cam`.
* **MQTT Broker:** Hosted on Node B via Eclipse Mosquitto. Accessible at `mqtt://192.168.1.44:1883`. 
    * *Topics:*
        * `outpost/doorbell` — Node A publishes `{"event": "ring"}` on doorbell press
        * `frigate/events` — Frigate publishes on person detection
        * `outpost/open_door` — Node B publishes `{"event": "open"}`; Node A subscribes and activates the door-release relay for 500 ms

## 3. The Cognitive Pipeline (Data Flow)

1.  **Telemetry:** Node A streams the live RTSP feed to Node B.
2.  **Edge AI Filter:** Frigate (Node B) consumes the RTSP stream, uses the native PCIe Coral TPU to detect the `person` class, and publishes an event to the local MQTT broker.
3.  **Physical Trigger (inbound):** Node A GPIO 17 detects doorbell press via PC817 optocoupler → publishes `{"event": "ring"}` to `outpost/doorbell`.
4.  **Notification:** OpenClaw (Node B) subscribes to MQTT. Upon receiving a person or doorbell event, it fetches the snapshot from Frigate's local REST API and sends it to the user's Telegram with a fixed caption. No external API key is required for this base flow. Optionally, if `USE_LLM=true` and a `GEMINI_API_KEY` is configured, OpenClaw will instead send a natural language description of the snapshot generated by the Google Gemini API (`gemini-1.5-flash`).
5.  **Output:** OpenClaw sends the snapshot image and caption directly to the user's mobile UI (Telegram).
6.  **Door Release (outbound):** User sends `/abrir` via Telegram → OpenClaw publishes `{"event": "open"}` to `outpost/open_door` → Node A receives it, activates GPIO 18 relay for 500 ms → Fermax electric strike opens.
